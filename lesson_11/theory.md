
# 🔐 bcrypt — хэширование паролей

## 📌 Что это такое

**bcrypt** — это алгоритм для **безопасного хэширования паролей**.

Главная идея:
👉 **никогда не хранить пароли в открытом виде**, только их хэш.

---

## ⚙️ Как работает bcrypt

bcrypt делает несколько вещей:

### 1. Соль (salt)

* К паролю добавляется случайная строка (salt)
* Даже одинаковые пароли → разные хэши

### 2. Хэширование

* Используется адаптивный алгоритм (основан на Blowfish)
* Результат — строка фиксированной длины

### 3. Cost factor (сложность)

* Параметр, который регулирует “медленность”
* Чем выше → тем безопаснее, но дольше вычисление

---

## 🔁 Проверка пароля

bcrypt не расшифровывает пароль.

Вместо этого:

1. Пользователь вводит пароль
2. bcrypt хэширует его с тем же salt
3. Сравнивает с сохранённым хэшем

---

## ✅ Почему bcrypt хорош

* Защита от brute-force (медленный)
* Автоматически использует salt
* Устойчив к rainbow tables

---

## ❗ Ограничения

* Только для паролей (не для токенов или данных)
* Медленный — не подходит для всего подряд

---

# 🎟️ JSON Web Token (JWT)

## 📌 Что это такое

**JSON Web Token** — это стандарт для **передачи данных между клиентом и сервером** в виде токена.

Используется для:

* авторизации (login)
* сессий без хранения на сервере (stateless)

---

## 🧱 Структура JWT

JWT состоит из 3 частей:

```
HEADER.PAYLOAD.SIGNATURE
```

### 1. Header

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

### 2. Payload (данные)

```json
{
  "userId": 123,
  "role": "admin"
}
```

⚠️ НЕ шифруется — только кодируется!

### 3. Signature (подпись)

Создаётся с помощью:

* секрета (secret key)
* или приватного ключа

---

## 🔐 Как работает JWT

### Процесс входа:

1. Пользователь логинится
2. Сервер:

   * проверяет пароль (через bcrypt)
   * создаёт JWT
3. JWT отправляется клиенту

---

### 📡 Дальше:

Клиент отправляет токен в каждом запросе:

```
Authorization: Bearer <token>
```

Сервер:

* проверяет подпись
* извлекает данные

---

## 🔁 Stateless модель

JWT позволяет:
👉 НЕ хранить сессии на сервере

Все данные уже внутри токена.

---

## ✅ Плюсы JWT

* Быстро
* Не требует хранения сессий
* Удобно для API и микросервисов

---

## ❗ Минусы

* Трудно “отозвать” токен
* Payload доступен (не секретный!)
* Нужно аккуратно хранить secret

---

# 🔗 Как bcrypt и JWT работают вместе

Типичный flow:

1. Регистрация:

   * пароль → bcrypt → сохраняем хэш

2. Логин:

   * сравниваем пароль через bcrypt
   * если ок → создаём JWT

3. Дальше:

   * клиент использует JWT для доступа

---

# 🧠 Важные практики

### bcrypt

* Используй cost factor ~10–14
* Никогда не храни raw пароль

### JWT

* Не клади чувствительные данные в payload
* Используй expiration (`exp`)
* Храни токен безопасно (HttpOnly cookie лучше)
